# DevOps Test Task

Данный репозиторий содержит выполнение тестового задания по автоматизации проверок HTTP-статусов.
## Структура проекта

```text
devops-test-task/
├── section1/                 # Раздел 1: Базовый скрипт на Python
│   ├── script.py             # Скрипт проверки статусов (1xx-3xx инфо, 4xx-5xx исключения)
│   └── requirements.txt
├── section2/                 # Раздел 2: Контейнеризация приложения
│   ├── Dockerfile            # Инструкции для сборки образа на базе ubuntu:22.04
│   ├── requirements.txt 
│   └── script.py             # Копия скрипта для изоляции сборки
├── section3/                 # Раздел 3: Автоматизация инфраструктуры
│   ├── inventory.ini         # Файл инвентаризации Ansible (local)
│   └── playbook.yml          # Сценарий установки Docker и запуска приложения
├── .gitignore                # Исключения для Git
└── README.md                 # Документация проекта
```
## Инструкции по запуску
Проект разделен на три независимых этапа. Вы можете запустить любой из них.

Раздел 1: Локальный запуск скрипта
Скрипт выполняет 5 запросов к сервису https://httpstat.us, логирует успешные ответы и генерирует перехватываемые исключения при кодах ошибок.

```Bash
cd section1
python3 -m pip install -r requirements.txt
python3 script.py
```
Раздел 2: Запуск в изолированной среде (Docker)
Скрипт и его зависимости упакованы в легковесный Docker-образ на базе официального образа Ubuntu.
```Bash
cd section2

# Сборка образа
docker build -t http-checker-image .

# Запуск контейнера в фоновом режиме
docker run -d --name my-checker-run http-checker-image

# Просмотр результатов проверки
docker logs my-checker-run

# Очистка (удаление контейнера)
docker rm -f my-checker-run
```
Раздел 3: Полная автоматизация (Ansible)
Playbook автоматически подготавливает хост: устанавливает необходимые пакеты, настраивает ключи репозиториев, устанавливает Docker, добавляет пользователя в нужную группу, собирает образ и запускает проверку с автоматическим выводом логов.
```Bash
cd section3

# Запуск автоматизации
ansible-playbook playbook.yml -K
```
## Возможные улучшения
1) Можно написать Unit-тесты), чтобы гарантировать правильную обработку статус-кодов без реальных сетевых запросов.
2) Перейти на docker-compose, чтобы легко добавлять новые контейнеры (например БД для хранения логов)
3) Добавить роли для Ansible
